<p class="lead">THE STANDARDS REPOSITORY &mdash; At 5:18 PM Central on Friday, November 20, the BSV standards repository merged exactly one pull request. <a href="https://github.com/bsv-blockchain/BRCs/pull/388">Pull request #388</a>, "Amend BRC-229 scalar derivation for ECPM security fix," changed one file, adding 46 lines and removing 17. Its commit is titled "docs(brc-229): specify nonzero hashed scalar and self disclosure." No new BRCs arrived. TNT has priced the week at 150 satoshis, a figure that is nonzero and, the paper confirms, not linear in anything.</p>

<h2>A Standard for Poker Night</h2>
<p><a href="https://brc.dev/229">BRC-229</a>, "Wallet-Native Elliptic Curve Point Multiplication as a BRC-98 Module," first merged on August 31. It defines <code>ecpm</code>, a <a href="https://brc.dev/98">BRC-98</a> permission-module scheme that lets a wallet apply a secret, wallet-derived secp256k1 scalar to "an arbitrary caller-supplied curve point," or remove it again with the modular inverse. The point is commutative masking: <code>a&middot;(b&middot;P) = b&middot;(a&middot;P)</code>. The standard's own example is Barnett-Smart mental poker, where every player masks the deck and later unmasks it in any order, and the app must never learn the scalar.</p>
<p>It does this without adding a single method to <a href="https://brc.dev/100">BRC-100</a>. Requests travel over the existing <code>getPublicKey</code> call, under a protocol name shaped like <code>p ecpm &lt;operation&gt; &lt;pointHex&gt; &lt;logicalProtocolID&gt;</code>, and the wallet answers with an ordinary <code>{ publicKey }</code>. BSV, in other words, has a standards-compliant way to play cards over a method named after something else. TNT finds this very on brand.</p>

<h2>What the Old Text Did</h2>
<p>Until Friday, the scalar <code>d</code> was simply the <a href="https://brc.dev/42">BRC-42</a>/<a href="https://brc.dev/43">BRC-43</a> child private key for the protocol. The new "Hashed scalar" section explains why that was a problem. A BRC-42 child key has the form <code>c = r + o</code>: the wallet's root key <code>r</code>, plus an offset <code>o = HMAC(S, invoiceNumber)</code> keyed by the shared secret between the wallet and the counterparty. For counterparty <code>anyone</code>, the spec notes, "anyone can compute <code>o</code>." For a counterparty key the caller holds, the caller computes it too.</p>
<p>So a caller could hand the wallet a third party's identity key <code>Q</code>, get back <code>c&middot;Q</code>, subtract <code>o&middot;Q</code> and keep <code>r&middot;Q</code>, which is "the wallet's root ECDH shared secret with that third party, at security level 0 and with no prompt." Pointing it at the wallet's own identity key gave up <code>r&middot;I</code>, the shared secret for counterparty <code>self</code>. That is the "self disclosure" in the commit title. It is not, TNT regrets to report, a wellness term. From those secrets a caller could recompute <a href="https://brc.dev/2">BRC-2</a> symmetric and HMAC keys, decrypt wallet data encrypted to <code>self</code>, and link derived public keys. The spec adds that it "would not expose signing keys." Your coins stayed put. Your diary did not.</p>
<p>The fix was coordinated as <a href="https://github.com/bsv-blockchain/ts-stack/security/advisories/GHSA-m3c6-3mv8-j86f">GHSA-m3c6-3mv8-j86f</a>, rated high, published at 4:03 PM Central the same Friday. The standard caught up 75 minutes later. The pull request says the patched package, SDK and toolbox versions were coordinated "before this specification PR was opened." For once, the paperwork was the last to know. TNT has covered paperwork before and was moved.</p>

<h2>Forty-Eight Bytes, Two Labels, One Plus Sign</h2>
<p>The wallet must now first derive the child key <code>c</code> as before, then feed it to HKDF-SHA256 (RFC 5869). The salt is <code>"BRC-229 p ecpm scalar v1"</code>, the info string is <code>"BRC-229 p ecpm scalar"</code>, and it expands 48 bytes. The result is reduced mod <code>n &minus; 1</code>, and then one is added. That plus sign is the "nonzero" in the title: the mapping "always yields a scalar in <code>[1, n)</code>, without a zero-retry rule," and the extra 16 bytes keep the reduction's bias "below 2&#8315;&sup1;&sup2;&#8312;."</p>
<p>The child key is now on a short leash. <code>c</code> "MUST be used only as HKDF input. It MUST NOT be used as the ECPM scalar, multiplied by a caller-supplied point, or returned." Because <code>d</code> "is not linear in <code>c</code>," a known offset can no longer be stripped from <code>d&middot;Q</code>. Round-trip removal and commutativity survive, since they only need <code>d</code> to be a fixed function of the derivation identity. The poker still works. It just works without tattling.</p>
<p>The conformance vectors were replaced, though the underlying BRC-42 child keys are unchanged. Vector 4's new scalar begins <code>00a16e91&hellip;</code>, and the spec says its leading zero byte "also exercises the fixed 32-byte width of <code>d</code> when it is encoded." The reference package, <code>@bsv/ecpm-permission-module</code>, is fixed from 0.2.0 on. Versions 0.1.x used the child key directly and are named in the advisory.</p>

<h2>A Rare Admission of Modesty</h2>
<p>The amendment also edited the security considerations. The old text said "an adaptively selected valid point does not weaken this assumption." The new text says the construction "does not claim that chosen points leave the work factor unchanged." TNT recognizes this as growth.</p>
<p>Two SHOULDs were added. Wallets should bound "operation counts per session" as well as concurrency and resources. A protocol that needs origin-scoped authorization should use security level 1 or 2, because "level 0 permits any origin to use the derivation identity without a prompt." The new Revision History entry ends: "Implementations of earlier revisions are not interoperable with this one." The pull request is more specific: masks from 0.1.x "cannot be removed with 0.2.0," and players "should finish or restart in-progress protocols on one version." Anyone mid-hand on Friday evening is advised that the river is now a different river.</p>
