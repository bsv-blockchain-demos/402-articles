<p class="lead">THE STANDARDS REPOSITORY &mdash; In the space of 28 hours last week, the BSV standards repository changed its license, added a NOTICE, added a PATENTS file and put one of its own Merkle proofs on a diet. Three pull requests merged between 12:10 PM Central on Tuesday, November 10, and 4:03 PM Central on Wednesday, November 11. None of them created a new BRC. TNT has priced the week at 150 satoshis, a figure the new license does not regulate.</p>

<h2>The Repository Gets a License of Its Own</h2>
<p><a href="https://github.com/bsv-blockchain/BRCs/pull/379">Pull request #379</a>, "Relicense under Apache License 2.0," touched 32 files and changed, by its own account, nothing else. It adds a <code>LICENSE</code> file containing the exact text of the Apache License, Version 2.0. TNT downloaded the official copy from apache.org and compared the two. They are identical, down to the last blank line.</p>
<p>Until last Wednesday, the repository had no license file at all. Its README said everything in it was "subject to the Open BSV License," and linked to the license file in a different repository. The standards had been borrowing their legal terms from next door, the way a student borrows Wi-Fi. They now have their own.</p>
<p>Twenty-four individual standards had their own Copyright section saying "This BRC is licensed under the Open BSV license." All 24 now say "Apache License 2.0," including the overlay standard <a href="https://brc.dev/178">BRC-178</a>, extended format <a href="https://brc.dev/30">BRC-30</a>, <a href="https://brc.dev/62">BRC-62</a>, which is BEEF, the Merkle path family (<a href="https://brc.dev/61">BRC-61</a>, <a href="https://brc.dev/71">BRC-71</a>, <a href="https://brc.dev/74">BRC-74</a>, <a href="https://brc.dev/119">BRC-119</a>) and a run of standards from BRC-124 to BRC-149. Three Rust <code>Cargo.toml</code> files in BRC-252's proof code went from <code>"MIT"</code> to <code>"Apache-2.0"</code>. The GitBook config's author line went from "Bitcoin Association" to "BSV Association," ending a long, unannounced period in which the repository's book was credited to an older name.</p>
<p>The same correction reached <a href="https://brc.dev/113">BRC-113</a>, the Merkle Proof Token standard, whose MIT block's "Bitcoin Association for BSV" line now reads "BSV Association." The pull request changed that one line. BRC-113 continues to carry the full text of Open BSV License Version 5 a few paragraphs above it. TNT offers no opinion on what that means and has referred the question to people who own more than one tie.</p>

<h2>A NOTICE, For Those Who Need to Be Noticed</h2>
<p>The new <code>NOTICE</code> file is five lines long. It says "Copyright 2023-2026 BSV Association" and then that the repository "includes software from these projects, under their own licenses": BRC-124, BRC-126 to BRC-135, BRC-139, BRC-142 to BRC-144, BRC-148 and BRC-149, "Copyright 2026 Jeff Harris (Apache-2.0)." That is 17 standards under a separate copyright line, all of them under the same license as everything else. TNT has counted twice.</p>

<h2>PATENTS, In Capitals, As Is Traditional</h2>
<p>Hours later, <a href="https://github.com/bsv-blockchain/BRCs/pull/381">pull request #381</a> added a 12-line file called <code>PATENTS</code>. It is written entirely in capital letters, which in legal documents is how one indicates sincerity. It states that "THE FOREGOING LICENSE APPLIES SOLELY TO COPYRIGHT IN THE SOFTWARE INDICATED, AS BSV ASSOCIATION (THE &ldquo;LICENSOR&rdquo;) HOLDS NO PATENT RIGHTS," and that the licensor "SHALL NOT, AND SHALL PROCURE ANY ENTITY LICENSING INTELLECTUAL PROPERTY TO THE LICENSOR SHALL NOT, ASSERT ANY PATENT RIGHTS AGAINST YOU" over use of the software "OR ANY WORK DERIVED FROM IT."</p>
<p>The rest is the familiar disclaimer: the software is provided "AS IS," without warranty, including warranties "REGARDING ENTITLEMENT." TNT notes that a document promising not to come after you also declines to promise you are entitled to anything, which is how the paper's subscribers already feel. The Association's own <a href="https://x.com/BSVAssociation/status/2120873889974636546">announcement</a> summarized it as "the patent holders behind it won&rsquo;t come after you," and said each relicensed repository includes a PATENTS notice. This one does.</p>

<h2>BRC-74 Loses 72 Bytes and Gains an Empty Array</h2>
<p>The day before, <a href="https://github.com/bsv-blockchain/BRCs/pull/378">pull request #378</a> rewrote the examples in <a href="https://brc.dev/74">BRC-74</a>, the BSV Unified Merkle Path (BUMP) format, so they match what <code>@bsv/sdk</code> 4.0.1's <code>MerklePath</code> actually produces. The binary and JSON field rules are unchanged. The difference is <code>trim</code>: the SDK drops any node it can recompute from the leaves already stored. In the standard's example proof, both level-1 hashes are parents of level-0 pairs, so level 1 now stores nothing. Its <code>nLeaves</code> is <code>00</code>, and the hex example went from 450 bytes to 378. The Merkle root, <code>57aab6e6&hellip;b483b4</code>, did not move.</p>
<p>The old hex "still parses" and remains "a valid BUMP; it is no longer what the SDK writes." The hand-rolled parser built on <code>require('bsv')</code> was replaced by <code>MerklePath.fromHex</code>, <code>computeRoot</code> and <code>toHex</code>, and a custom <code>combinePaths</code> function by <code>MerklePath.combine</code>. The pull request also points out that the JSON section still says each level contains "an array of one or more leaves," while the new example has an empty one. It declined to edit that sentence "because that would edit normative wording," and left it for a maintainer. TNT salutes a contributor who will delete 129 lines but not one normative sentence. BRC-74 was then edited again the next day, for its license. It made the news twice in one week by getting smaller.</p>

<h2>Meanwhile, on the Timeline: Is Freedom Safe?</h2>
<p>BSV X spent the week deciding whether this was good news. The BSV Times <a href="https://x.com/thebsvtimes/status/2120702853044162978">listed</a> TS Stack, BSV Wallet, Go Wallet Toolbox and the Python SDK among the toolkits moving to Apache 2.0. The Association promised <a href="https://x.com/BSVAssociation/status/2120873889974636546">"no lawyer needed"</a>, while noting that Teranode and SV Node stay under the Open BSV License. One observer called it a real improvement that <a href="https://x.com/WuTao2023/status/2120724118744293675">"does not mean the whole BSV stack is now standard open source."</a> Another said it <a href="https://x.com/mitansh_j07/status/2120727318058701042">"should finally make them usable outside BSV itself."</a> A third <a href="https://x.com/BitcoinSvGuide/status/2121632539144020339">argued</a> that the move conflicts with the Association's Articles of Incorporation. TNT reports the debate and does not adjudicate Swiss corporate law.</p>
<p>One recap <a href="https://x.com/jesterwyn/status/2121146942495596676">summed it up</a>: "Builders like it. A smaller, sharper slice does not." TNT observes that BSV is the only ecosystem whose main worry about open-sourcing its tools is that someone else might use them. TNT has been trying to get someone else to use them for eight years.</p>
<p>Eight is literal. BSV <a href="https://x.com/KallubiBSV/status/2122245058489454889">turned 8 on November 15</a>. For its birthday it got a relicensing schism and a wallet war. In the wallet war, one side <a href="https://x.com/cryptorebel_SV/status/2121726189903487409">asked</a> "How pathetic are these BRC nerds." TNT accepts the title and will print it on the masthead. A calmer voice said arguing over which wallet survives a million transactions per second is <a href="https://x.com/BSVSearch/status/2120681923596988650">"like agonizing over which restaurant to pick once you have a billion dollars in the bank,"</a> while BSV "is still working out how to pay the rent." Another <a href="https://x.com/1dead1b2/status/2121526257200287896">offered</a> a full interoperability standard in four lines, ending "You want to cry on Twitter, do it." Meanwhile, <a href="https://brc.dev/100">BRC-100</a>, which <a href="https://x.com/ProjectBabbage/status/2120751137917915541">standardizes app-wallet communication</a>, continues not to care which wallet you cry from.</p>

<h2>Capacity Desk</h2>
<p>A Teranode testnet run logged <a href="https://x.com/KallubiBSV/status/2121130796333343026">"504.73 GB, 2.83B tx."</a> Elsewhere, a defender of the chain <a href="https://x.com/Guillaume88745/status/2122518901846073574">pointed out</a> that a critic's own "BSV is dead" screenshot showed "over 200,000 confirmed transactions and 110 blocks produced in 24 hours." The network has the room for half a terabyte and, on some days, the traffic of a medium-sized bakery. The dead chain kept producing blocks throughout the argument about whether it was dead.</p>
<p>Your old phone, meanwhile, <a href="https://x.com/KallubiBSV/status/2121707524176896134">"just became a hardware wallet"</a>: airplane mode, QR signing, testnet beta, and "Open source (Apache 2.0) this month." BSV's answer to the hardware wallet industry turns out to be the drawer every household already has.</p>

<h2>At Press Time</h2>
<p>At press time, the Association had published an FAQ whose first question was <a href="https://x.com/BSVAssociation/status/2121307133039825185">"Is Calvin walking away from the BSV blockchain?"</a> and whose first answer was "No." TNT admires the format and has adopted it. Is the BSV standards repository now owned by lawyers? No. Did any BRC change what it does this week? No. Is BRC-74's level 1 empty? Yes, and <code>computeRoot</code> is fine with it. The PATENTS file was asked for comment and replied in capital letters.</p>
